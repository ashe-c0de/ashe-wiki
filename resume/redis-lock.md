分布式锁的核心机制：

- NX (Not Exists)：仅在 Key 不存在时才设置成功。这保证了只有一个请求能拿到锁。
- PX (Expiration)：设置过期时间（如 30,000 毫秒）。防止某个请求挂掉后，锁永远不释放导致“死锁”。
- unique_value：每个请求生成的随机唯一 ID。释放锁时需校验该值，防止“误删”他人的锁。

如何实现可重入锁？

假设A函数内部在调用其他服务的B函数（也有锁），若无法支持可重入锁，则会造成死锁。
通常的实现方式是将 Redis 的数据结构从 String 改为 Hash：
Key: 锁的名称（如 order_lock_123）。
Field: 请求的唯一标识（如 UUID + ThreadID）。
Value: 重入计数器（整数，初始为 1）。

执行逻辑：
尝试加锁：
如果 Key 不存在：直接加锁，设置 Field 为当前线程，Value = 1。
如果 Key 已存在：
判断 Field 是否为当前线程。
如果是：Value 自增 1（hincrby），加锁成功。
如果不是：加锁失败，进入等待/重试。

如何实现自动续约？

为了保证请求的行为执行完毕，有一个后台定时任务自动续约（延长key的过期时间），当行为执行完会调用unlock删除key，确保行为执行完成再释放锁。
